Warehouse/placement/frozen_tier.py

layer wh_placement

Ticket 03 (phase-2 campaign): FrozenTier sorts one tier's candidates once per drain (D map, per-aisle and per-(aisle, bracket) stable D-sorted buckets, appearance orders); TierSlice overlays one exclusion set per pool open with lazy-skipping cursors that speak the pools' deque/bucket protocol, recomputing aisle and bracket first-appearance order under exclusion so every tie-break is byte-identical to the eager build. Since 2026-09-20 a TierSlice may also carry a caller's template STORE: the first open over a (tier, exclusion set) builds that structure and every further open of the same round reads it copy-on-write (_CowAisles / _CowBuckets / _CowInner), with _Cursor.clone copying only the three position fields, so a pool that seats ~12 units clones ~12 cursors instead of rebuilding ~4,200.
