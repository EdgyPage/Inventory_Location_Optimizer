`python -m Schema.store_index --check`: exit 1 if the committed shape store is stale. THE GATE THE STOP HOOK IS NOT. `Schema/hook_check.py` runs this same `stale_reasons()` at the end of every turn and ALWAYS exits 0 -- advisory by design, so it can never block. Advisory means ignorable, and on 2026-09-18 it was: two DDL-defining sources (`Warehouse_Data.py`, `runtime_metrics.py`) were edited and committed with every gate in CLAUDE.md section 1 green, and the only check that noticed -- `test_schema_compatibility.py::test_the_committed_index_is_current_with_the_tree` -- sits in the slow architecture tier that a routine `Tests/unit Tests/integration` subset never reaches. `Schema.profile_tree --check` already gave the OTHER store in this directory a blocking form; this is the DB-shape store's, and it is the hook's own cheap read (file hashes and document stats, no writer imports), so it costs well under a second. `--check` is accepted for symmetry with the other gates and is also the default: there is nothing else this CLI could do, because `scripts/schema_report.py --sync` is the only writer.
