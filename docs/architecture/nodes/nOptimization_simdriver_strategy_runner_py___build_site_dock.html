The SITE's dock, yard and receiving coordinator -- or None when the unit fields none. None is the coupled INBOUND-OFF pole, which the funnel runs in every cell (site-dock 06): no trailer type is named, so no transit exists, each leaf keeps its own batch lead queue byte-identically and `check_reorders` stays each leaf's own composition. That is a real configuration, not a degenerate one, so it is a return rather than a refusal. Everything else about a coupled unit's inbound IS refused rather than degraded, because every degradation here is the double count with a coupled label on it: * a NON-STANDING trailer pipeline -- the v1 drain runs through each manager's own dock deque, so two leaves would field two docks and two crews under one site's declared one, and no table would say so; * a standing yard with NO receiving crew -- a yard nobody unloads produces no receipts at all, silently, for the whole run; * two leaves carrying DIFFERENT inbound specs -- one site is one yard, and two specs would be two arrival calendars over one set of doors. THE PRICE LIST IS BUILT HERE (site-dock 27). The unload price is a statement about the MERCHANDISE, so the dock holds one `UnloadCost` per regime, each derived from ITS OWN channel's pick config through the same picking -> put-away -> receiving chain a leaf builds for itself. The two constants that exist today ARE the two entries, which is why an uncoupled run is untouched: it constructs no list at all.
