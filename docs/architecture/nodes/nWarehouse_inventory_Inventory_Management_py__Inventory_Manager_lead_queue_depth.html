function lead_queue_depth

@property
def lead_queue_depth(self) -> int
In-flight transit ENTRIES: lead-queue records flag-off, trailers flag-on. Through the transit's own census, NOT the `_lead_queue` shim below: the shim exposes `BatchTransit`'s entry list and a trailer transit has no such list — the first e2e run with the trailer flag on found exactly that AttributeError here. For `BatchTransit`, `depth` IS `len(entries)`, so flag-off reads are unchanged. REFUSES on a coupled leaf, for `in_transit_qty`'s reason and with a sharper edge: under a trailer pipeline an in-flight ENTRY is a TRAILER, and a trailer's load is mixed by construction — so this level is the whole site's and reporting it per leaf would double the site's in-flight count across the pair's two DBs (the shape ADR-0005 rejected in as many words). The site-scoped replacement counts this leaf's own in-flight LOTS instead, which is what `BatchTransit.depth` counted before the trailer pipeline existed and the only reading that both decomposes and sums.
