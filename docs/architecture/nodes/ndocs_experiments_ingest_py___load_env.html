def _load_env(path: str) -> None
Inject KEY=VALUE pairs from *path* into os.environ (shell vars take priority). Byte-for-byte the entry-script idiom in `Warehouse/generation/generate_mixed_profile.py` and `generate_profile_suite.py`; `Optimization/config/sim_config.py` carries its own. WITHOUT this, `--profiles-root`'s documented `$PROFILE_INPUT_DIR` default could never populate: the key lives in `.env`, nothing here read it, so `os.getenv` returned None, `_inv_root_from_bindings` returned at its first guard, and BY-NAME catalogue resolution silently fell through to the per-leaf meta file's recorded ABSOLUTE `inv_db` — the one route pair_bindings exists to replace, and the one that does not survive a moved drive. No warning was emitted, because the fallback is a legitimate path for pre-v2 runs.
