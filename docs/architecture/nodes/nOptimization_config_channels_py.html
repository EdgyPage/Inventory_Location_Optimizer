Optimization.config.channels
channels.py — the Channel abstraction: one operation over a shared warehouse. A *Channel* bundles the three things that differ between the store and fulfillment operations while the pick MECHANICS stay shared: * regime — which SKU family / bins it uses (BinKey routing; see regime.py) * batch stream — its own order-generation rate/size (a BatchConfig, built per run once the channel's SKU-subset size is known) + an independent seed offset * picker pool — its own worker count + cost regression (a PickerProfile wrapping a PickConfig) The channel list is the single source of truth the runner uses to (a) generate a batch stream per channel, (b) simulate each channel with its own picker pool + cost, and (c) derive ``WP_BY_REGIME`` for the per-regime cost routing in placement/labor. Adding a new operation later = adding one Channel. Backward-compatible: a run with a single ``store`` channel reproduces today's behavior exactly (one batch stream, one picker pool, one cost, one DB subtree).
