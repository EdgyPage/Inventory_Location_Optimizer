def _prepare_site_run(channel_runs, mixed: bool, shared: dict, pair_dir: str, log: logging.Logger, workers: int=1, resume_granularity: str='strategy') -> tuple[list, list]
Pre-initialise ONE pair's COUPLED runs: two channel leaves per work unit. `_prepare_channel_run` survives unforked and is called once per channel (site-dock 02 section 3) -- each leaf genuinely needs its own run dir, batch stream, pick config, wp, yardsticks and DB, and every one of those stays per channel under coupling. What this adds is only the pairing: the two channels' ordered arm lists zipped into arm PAIRS, the site crews lifted out of both leaf payloads to unit scope, and the two group keys carried on the unit so no parent-side reader has to slice a uid for them. Returns (unit_args_list, sim_skeletons) in the same shape `_prepare_channel_run` returns, so `_build_work_units` composes them identically.
