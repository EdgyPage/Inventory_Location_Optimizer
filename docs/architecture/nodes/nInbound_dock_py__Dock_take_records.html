function take_records

layer inbound · file Inbound/dock.py

def take_records(self) -> list
This batch's unload records, WITHOUT restarting the crew's clock. `drain_records` is this plus the reset, and the reset is the half that has exactly ONE owner. Uncoupled that owner is `drain_records` itself and nothing calls this; on a coupled run the site's receiving coordinator partitions these rows between two leaves and the reset belongs to `SiteReceiving.note_records`, which fires once both leaves have stamped — so the coordinator needs the rows without the reset rather than a second reset it would have to undo.
