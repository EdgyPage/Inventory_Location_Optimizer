def overrides(self) -> dict
What this cell CHANGES, as a plain record. The same four values `_apply_cell` writes, named rather than positional, so a caller can see a cell's effect without applying it — which is what a resolution pass needs, and what makes the effect diffable between two cells. `scheduler` is a pick-config field (like `one_way`), so it lands on every one of a channel's pick-config dicts; `aisle_split` and `velocity_zoning` are channel-level. `inbound` is the odd one out and stays named as itself: the yard and dock policies are whole-RUN settings on `CONFIG['global']`, which is exactly why they had to become a cell axis instead of six separate runs.
