{'repo_commit': <short sha> | 'unknown', 'repo_dirty': True | False | None}. WHY THIS MUST NOT RAISE: it runs at the front of every simulation, and a run that dies because provenance could not be derived is strictly worse than a run that records `unknown`. A shallow clone, a source export with no `.git`, a machine with no git on PATH and a wedged index lock all resolve to a recorded value rather than an exception. `repo_dirty` is deliberately THREE-valued: True/False are answers, `None` means "not established" — which is what an export or a missing git binary honestly is, and reading it as "clean" would be the one wrong inference.
