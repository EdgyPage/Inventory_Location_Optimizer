def _partner_centroid_over(partners, inner, live_inner, row, freq_by_idx)
`_demand_weighted_partner_centroid` over a copy-on-write aisle view (`inner`, a `gain_cow._CowInner`), walking only the members that can contribute. The full walk folds `inner.items()` in the view's order -- the live keys in live order (the view's copied list in place of the live one), then the keys the view created, in creation order -- and a member adds nothing unless the row lifts it. So the same fold is: `partners` (the aisle's LIVE members that the row lifts, in live order; fixed for the drain, since no virtual placement moves the live book), each read through the view, then the view's created keys that the row lifts. Same members, same order, same arithmetic, same floats (S10 of `.scratch/inbound-fullscale-perf/`).
