def drive(self, i: int, pool) -> dict
Run site day `i`'s seven phases across every bound leaf; return what each triggered, keyed by `id(leaf)`. THE WHOLE COMPOSITION, ONCE -- never each leaf's own `check_reorders`. Phase 5 is routed from inside `SiteReceiving.drain`, which is the only placement that puts the site's receive BEFORE every leaf's put drain; run through the leaves' own compositions instead and the earlier leaf's put drain fires before the site has unloaded anything, so its receipts wait a whole batch for a bin (site-dock 21's hand-off list says this in as many words). Both deadlines are SITE values and both accessors are idempotent per site day, so asking here and asking again inside a leaf returns the same answer rather than two.
