function _co_by_aisle

layer wh_placement · file Warehouse/placement/Assignment_Functions.py

def _co_by_aisle(row, idx_sets, partner_aisles, freq_by_idx) -> dict
{aisle: Σ (lift - 1)·f_i over the SKU's partners i placed in that aisle}, for every aisle that holds at least one partner -- and NOTHING for the aisles that hold none. BIT-IDENTICAL TO `_delta_lift_from_row` PER AISLE, by construction rather than by tolerance, because the placement oracles compare exact floats. That function is a left fold from int 0 in one of two orders, chosen per aisle by `len(row) <= len(members)`: * row order, filtered by membership, when the row is the shorter side. The fold here walks `row` once in that same order and adds each partner's term to every aisle the inverse book says holds it -- so each aisle receives exactly the terms the old generator yielded for it, in the same sequence, from the same int 0. * SET order over the aisle's members when the members are the shorter side. A set's iteration order is not the row's, so those aisles are re-folded the old way, and only those: touched aisles whose member set is shorter than the row. An aisle the inverse book never names had an empty intersection, for which the old fold returned int 0 (`sum` of nothing); the caller reads a missing key as that same int 0. Cost: O(|row| + Σ partners' aisles + Σ members over the re-folded aisles), against the old O(live aisles × min(|row|, |members|)) -- the k 1.98 term the scan-width ladder found.
