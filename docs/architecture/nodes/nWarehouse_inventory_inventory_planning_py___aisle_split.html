layer wh_inventory · file Warehouse/inventory/inventory_planning.py

def _aisle_split(a_w: int, target_bins: int, eff_fn, bin_width: int, k, capacity_loss)
Cut an aisle of width `a_w` (holding `target_bins` bins for its bucket) into `k` shorter segments of width ~a_w/k, modeling cross-aisle throughways that consume `capacity_loss` of the bins. Under one-way lanes, shorter aisles ⇒ less x-traversal. Returns (seg_w, n_segments, seg_eff, cap_total) or None (no split ⇒ byte-identical caller path). `eff_fn(width) -> bins-per-segment` (uniform_aisle_bins or catalog_aisle_bins bound to the tier). k is bounded to ≤ a_w // bin_width (≥1 column/segment) and ≤ MAX_AISLE_SPLIT_K so the emitted aisle count cannot blow up. Total usable bins ≈ target_bins·(1-capacity_loss): the bins in the throughways are genuinely sacrificed HERE. WHAT THE SPLIT NOW MEANS, which is not what it used to. The loss no longer reaches the inventory: `_split_inflation` adds the compensatory aisles at SIZING time, so a split bucket is asked for `1/(1-loss)` times the replicas and the run still holds its declared levels ("Field the floor", decision 9 — the line floor is a promise, and a throughway is not a reason to break it). A split arm therefore trades AISLES for travel, not capacity for travel; it used to raise fill by shrinking the shelf under a fixed stock, and an archived `ks` sweep measured that older trade, so its results are not comparable to a new one.
