Optimization.runschema.sim_manifest
sim_manifest.py — run bookkeeping artifacts. Resume state (resume.pkl) + the top-level run_manifest.json schema index that the docs ingest (docs/experiments/ingest.py) auto-discovers a run from. It also stamps CODE provenance into run_spec.json (`repo_commit` / `repo_dirty`). That is a different question from the two ids already on a run and neither of them answers it: ``run_layout.json``'s ``schema_id`` names the run-TREE contract and ``sim_meta.json``'s ``sim_schema_id`` names the DB TABLE contract, so a change to the simulator that moves no path and no column — `753d01e` moved absolute throughput ~1.4 % without touching either — leaves both byte-identical and the two runs indistinguishable.
