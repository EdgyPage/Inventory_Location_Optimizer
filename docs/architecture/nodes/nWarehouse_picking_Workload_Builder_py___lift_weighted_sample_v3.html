function _lift_weighted_sample_v3

layer wh_picking · file Warehouse/picking/Workload_Builder.py

def _lift_weighted_sample_v3(candidates: list, k: int, affinity: 'AffMatrix | AffinityStore | None', rng: random.Random | None=None) -> list
Segment-tree form of `_lift_weighted_sample`: the same conditional-demand weight model (weight(B) = freq(B) · Π lift(A,B) over selected partners A) and the same O((k·(1+P))·log n) cost as v2, but drawing k DISTINCT candidates — which v2 does not. v2 returns `k` entries of which a measured 8.64% (fulfillment) / 1.02% (store) are repeats of a SKU it has already drawn; `Batch.items` is keyed by sku, so the repeats collapse and the batch silently delivers fewer lines than the era declared. The cause is `_Fenwick`'s subtractive update under this model's enormous weight dynamic range; `_SegTree` removes it. NOT byte-compatible with v1 or v2 — a different draw sequence is the whole point, so this is a new results era (BatchConfig.sampler='v3'; batch_precompute fingerprints it apart). Deterministic for a given rng seed, one rng.uniform consumed per draw like v1 and v2.
