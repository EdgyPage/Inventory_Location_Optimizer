layer wh_catalog · file Warehouse/catalog/Affinity_Store.py

def _db_stamp(self) -> tuple[int, int, int, int]
(main size, header change counter, mtime_ns, -wal size) — identity of the DB. The WAL size is load-bearing: this store opens in WAL mode, so a committed write lives in `affinity.db-wal` and the MAIN file's header does not move until a checkpoint — size+counter alone would serve a stale sidecar over fresh commits. A reader-created `-wal` is zero bytes and a clean writer close removes it, so the production read-only file stamps identically across opens. mtime_ns catches a REGENERATED file: a deterministic generator can reproduce both the size and the commit count, and a copied/restored file changing mtime only costs one spurious SQL reload — the safe direction.
