Optimization.Performance_Evaluations.yard
yard — did the yard bind, and what did the inbound policy cost in trailer-days. The tenth chart family, and inbound's FIRST figure coverage of any kind: the receiving surface (`batch_stats.recv_*`) has been carried into frames and one diagnostics report since it landed and is declared by zero quantities. ## What this family answers, and what it deliberately does not The campaign behind it asks one two-part question — does space-aware inbound beat FIFO, and at what fee cost — so this folder holds the second half. The first half is hours, and hours live in `labor`/`headline` where they always have. **The two never meet in a number.** Labour seconds and detention days are different instruments; the only place they compose in this whole effort is the `gain_gated` arm's urgency GATE, which is a yes/no test inside the simulation and not a report. A single score blending them would be exactly the arithmetic the fee proxy was designed to avoid. ## The fee is a PROXY, and the stamps are raw Nothing in the database is a fee. `yard_trailers` holds arrival, staging and emptying stamps; the detention span, the overage past `INBOUND_FEE_THRESHOLD_DAYS` and the door utilization are all derived here, at read time, against the threshold the RUN recorded. That is what makes a finished run re-reportable under a different threshold without re-simulating — and it is why the calibration probe ("where does the threshold sit for a nonzero, non-saturated overage?") is an analysis pass over one FIFO run rather than a sweep. Overage days are never converted to money. ## An empty folder here is a result A run without `INBOUND_STANDING_YARD` has no yard — not an empty one. The `yard` request is DENIED when no arm carries a trailer row, so these evaluations render nothing and the driver logs why. Zeroed bars would be a claim about a model that did not run.
